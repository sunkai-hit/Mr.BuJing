# 六卷项目化重构方案（V0.2）

> 这是对原V0.1六卷总纲的**增量深化**。五项确认基准不变。现实项目只提供通用业务母题，具体事故与人物矛盾由小说独立虚构。参见 [改编规则](../project-materials/00-现实项目仙侠化改编规则.md) 和 [30个故事种子](../project-materials/01-第一批30个需求故事种子.md)。

## 两条成长线
- **外部交付线**：内部小需求→宗门商业化→跨宗平台化→资源与身份治理→天道系统危机→天道共同治理。
- **内部人格线**：救火求活→尊重专业→愿意承担事故后果→相信小宗门也有需求权→承认自己受益于分配不公→放弃单一系统主权。
- 一项项目的成功，不等于人物成长结束；每卷都要让角色付出新代价。技术只是叙事工具，小说的主体仍是关系、选择和冲突。

## 第一卷（第1—40章）宗门求生与初次交付
**项目A，章1—10**：宗门灵石报销及物料领用基础流程（ERP基础流程原型），集中在申请、权限、查重、日志、用户体验、测试与运行维护。不要扩张成完整ERP。
**项目B，章11—40**：天剑宗护山大阵「运营控制与预警一期」（设备接入与安全监测原型），需要接口探查、旁路采集、告警、角色授权、追溯与事故应对。不是重造护山大阵，更不是九州御剑调度云。
**核心戏**：「甲方说零停机，旧阵图却是假的」；顾不惊作为组织者必须承认自己不懂底层阵法。第20章阶段方案评审收预付款2000；第39章终验收尾款5000；90日内还6000旧债，成本及来源按旧版台账执行。
**因果种子**：审批权限→第四卷身份治理；运维日志→第五卷审计追责；工程质量→第二卷事故主题。

## 第二卷（第41—80章）质量与制造
**A线：丹霞谷灵药WMS**：入库质检与复检节点、批次/效期、冻结库存、授权例外放行、托盘组拆、退库及追溯。必须让质检员提供结论、库管执行，授权者可承担风险例外，系统只提示/留痕，绝不把任何判定简化为「自动一票否决」。
**B线：天工宗仙器制造ERP**：设计稿版本/BOM、采购与议价、生产排产及插单、工序质检、仓储单位换算、箱号发运。让现实复杂性变成「一把飞剑出问题牵动十个工位」。
**卷中事故**：虚构一宗跨批次灵丹纠纷，问题由决策、流程、技术与责任叠加，不给主角或反派一锤定音的廉价答案。
**人物变化**：沈听澜要求质量底线，苏小满成为不可忽视的测试力量，白知微开始争取团队成果分配。

## 第三卷（第81—120章）九州御剑飞行云平台
**主业务**：机场/遥控法器直连仙讯云、公开接口、消息桥接、状态及任务调度、禁飞与授权、录像系统与告警系统的独立建设、跨宗协作与断链应急。云平台提供管理与调度，不包办所有飞行控制细节。
**核心冲突**：大宗门接口壁垒、设备标准不一、断网后的责任边界；技术统一与地方自治冲突。
**人物变化**：专业角色拥有独立解决危机的关键戏份。开放最低必要接口而非占有世界。
**结尾**：天庭接触并试图收编，世界从项目竞争进入规则争夺。

## 第四卷（第121—160章）万界灵讯与资源治理
**主业务**：共享灵脉资源、独享抽取和释放、单独长效独占线路、授权令牌/白名单、对外服务接口。运营管理平台负责授权与分配，真实流量走独立节点与线路，不能把后台描写成所有流量必经之处。
**旁线**：宗门弟子身份入网、命牌与设备绑定、共享识别、申请更换与封禁申诉。复杂隧道代理产品暂不作为优先母题。
**冲突**：资源稀缺、身份与接入权、强宗独占、系统权限谁发放；最终关联到天道的垄断分配。

## 第五卷（第161—200章）丹医辅助与系统事故
**主业务**：虚构的丹医谷病案辅助、方剂审核、科研整理，尽量低耦合接入。自动建议不能替代有资质的医修、风险判断和责任归属。
**冲突**：数据错误、过度信任模型、跨系统接口缺陷叠加，引发天道级事故。曝光系统奖励来自不公平的众愿之力聚集。
**人物变化**：顾不惊不再用「系统给我奖励」解释一切，面对自己曾参与不公分配的事实，拒绝永生任务。

## 第六卷（第201—240章）天道V2.0
**主业务**：汇聚前五卷经验：身份授权、需求公开、风险评审、审计留痕、跨宗共同治理、分域灰度上线与危机回滚。
**核心冲突**：允许众生表达需求与保障世界安全怎样兼容；技术专业性不能等于绝对统治。谢无策的动机必须有正当恐惧基础。
**结局**：取消天道唯一管理员机制，确保有专业审议和紧急措施；顾不惊和沈听澜回到合欢宗。
**尾声**：花照月提出「一键飞升」小需求，顾不惊拿出需求评审单，并没有从此不工作。

## 跨卷工程资产链
报销审批中的角色权限 → WMS质量例外的审计 → 御剑云的跨宗多租户 → 灵讯资源的资格和配额 → 丹医AI的专业责任 → 天道新治理的共识与回溯。
**每一次大型项目应当复用上卷的经验，同时暴露上一卷没有解决的问题**。

## 保留与禁止

禁止：第一卷完成全宗ERP/WMS、系统凭写文档直接加点、用吵架等于对线、直接拿真实客户数据、后期把技术系统写成万能神力。
