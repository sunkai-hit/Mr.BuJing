# 创作基准与六卷总纲（V0.2）
> 状态：五项创作基准已由作者确认；剧情细节为可修订策划。创建：2026-10-30。

## A. 不可擅自改变的五项基准
1. **喜剧爽文为主，后期逐渐史诗化**。第一卷以高密度反差笑点、能力升级、团队交付立住读者；第三卷扩大格局；第四至六卷以权力、制度和代价承接前期伏笔。严肃不等于抛弃幽默。
2. **单女主为主，宗门群像暧昧**。顾不惊与沈听澜走长期、平等、双向成就的情感线；其他女性拥有独立职业目标和戏份，暧昧不替代能力、行为与成长。不做露骨色情。
3. **男主技术一般，产品与管理能力出色**。懂软件开发流程和必要技术原理，可以读懂设计取舍，但不会凭空写出绝世阵法；强设计交付依赖沈听澜、苏小满、白知微等专业伙伴。
4. **六卷、约240章、80—100万字**。规划每卷40章、约13—17万字，章均约3300—4200汉字。精确字数在正式稿阶段校准，章节数量可微调但仍维持六卷长篇布局。
5. **改革天道后回归合欢宗**。男主不靠自己独占最高权限成神，而是完成众愿制度修复，放弃唯一管理员位置；最终生活重心回到桃花山与沈听澜及团队。

## B. 标题与类型
正名：《我在合欢宗做产品经理》；男主角：顾不惊，号「不惊先生」。标签：系统流、修仙、职场荒诞喜剧、团队群像、经营升级、轻度感情、后期规则博弈。
一句话：一个被现代甲方需求折磨的产品经理来到合欢宗，靠研发交付加能力、靠合理对线加生命，最后把运行十万年的天道重新做了一次架构治理。
主题命题：真正的能力不是无条件满足所有人的要求，而是帮助人们看见并解决真正的问题；系统不应该取代人的判断，也不应夺走协作中其他人的功劳。

## C. 叙事承诺与边界
- 每5章至少提供一次明确的幽默场面、可验证的进展或关系变化；每10章有一个阶段高潮；每卷有不可逆的外部变化。
- 不是现代软件术语堆砌：读者无需懂PRD、接口、数据库也能理解场景。技术讨论必须转化为冲突、风险和可见结果。
- 甲方不都是坏人，项目失败不都是程序员的错。宗门女性角色不被写成纯粹奖品。
- 系统给的是加速和反馈，不保证项目成功；重大方案需要调查、资源、专业人员、测试、上线、追责。
- 禁止通过任务拆分刷奖励；成功对线应达成真实共识，不是羞辱或压倒客户。
- 喜剧来源：权责错位、信息不对称、流程荒唐、职业黑话跨世界碰撞；反派实力、质量事故和人物感情需要被认真对待。

## D. 世界主命题和总线
十万年前，天道本是面向众生的「众愿系统」，允许生灵表达需要，由各域共议调整世界规则。长年的集中治理与兼容补丁使它变成垄断授权、层层依赖、拒绝变更的遗留平台。天工司掌司谢无策认为「消除需求方，就能消除不确定性」，准备锁死天道。合欢宗的共鸣术保有理解众愿的技术残片；顾不惊携带的「天道研发修仙系统」是失落的开发者终端，但其奖励分配机制已被旧秩序部分污染。
主线五级升级：个人生存 → 宗门扭亏 → 跨宗平台 → 天庭治理 → 重构众愿秩序。人物成长对应：救火 → 交付 → 建组织 → 担责任 → 放权。

## E. 六卷概要
### 第一卷《合欢宗不养闲人》（第1—40章）
宗门欠债6000标准灵石，九十天内不能偿还将被收回灵脉。顾不惊穿越并绑定系统，以宗门报销审批小功能建立信任，组建研发小队；接下天剑宗护山大阵的「运营控制与预警系统」项目，经历真假需求、验收边界、缺陷、变更和有人暗中阻挠，最终交付可用的一期工程。宗门渡过第一轮债务危机，天工司开始监控顾不惊。内部系统只是试点，外部项目则以分阶段验收为生存关键。
### 第二卷《甲方比心魔更难渡》（第41—80章）
承接丹宗灵药仓储与炼制协同、御剑飞行登记等项目，合欢宗从救火转为商业化。规模扩张暴露人力瓶颈与质量风险，事故调查迫使顾不惊接受「好看的交付报告可能掩盖真实损失」。沈听澜开始推动技术自治和质量闸门。
### 第三卷《七宗大比：不服就验收》（第81—120章）
合欢宗提出跨宗「九州御剑飞行云平台」，面对接口垄断、契约封锁和攻击。跨宗协作取得突破，白知微提出成果共享制度。男主不再靠个人解决所有问题，天庭招募并观察其影响力。
### 第四卷《天庭甲方：需求永不冻结》（第121—160章）
天庭运营十万年的因果、轮回、灵气分配与飞升审核平台层层腐朽。顾不惊发现严重规则缺陷与受损人群，接触众愿系统旧记录，公开挑战一条不合理的天规。系统处罚出现，揭开前任天道架构师被抹除的秘密。
### 第五卷《所有人都说只是小改》（第161—200章）
谢无策计划永久冻结天道；男主发现系统属性奖励从众愿之力中集中抽取，自己曾是旧体系受益者。拒绝成为新的绝对管理员，失去主要系统特权。天道危机引爆，团队出现真实分歧，但最终重新汇合。
### 第六卷《天道V2.0：本次更新不需要甲方》（第201—240章）
所有宗门共议变更、分域试运行、可回溯审计、独立监督与紧急纠错。顾不惊以组织者与架构协调者身份推动落地，而非单人写出无敌代码；谢无策与其争夺天道的治理权。最终旧特权机制退出，新机制保留人性与不完美，顾不惊与沈听澜回到合欢宗，过能接纳「合理小需求」的日子。

## F. 伏笔—回收总账
- 第一章的「符合真实意愿」提示：第四卷揭示众愿制度起点，第六卷兑现权利。
- 合欢宗共鸣术能看情绪却不能自动写需求：第三卷成为群体需求治理的基础，第六卷成为众愿入口。
- 能力奖励归属不透明：第二卷出现团队不满，第三卷白知微质疑，第五卷揭示代价。
- 古旧验收契约中的「唯一确认人」：第一卷出现，第四卷对应天道单点审批。
- 副作用未记录的神秘扣值：第一卷偶有征兆，第五卷破局。
- 谢无策的「无用户无变更」：第三卷有影子，第四卷登场，第六卷正面辩论。

## G. 已确认与待确认
已确认：五项基准、系统核心玩法、顾不惊与沈听澜的双主角关系、六卷收束方向。
暂定草案：宗门财务数字、角色具体年龄、修炼境界、第一卷合同金额与章节节点，写正文时需先做一致性复核，不得无标记改动。

## H. V0.2 新增：现实项目驱动的长期故事引擎

**冻结设定不变**：喜剧爽文后期史诗化、单女主沈听澜、男主技术一般但产品与管理强、六卷80—100万字、改革天道后回合欢宗。改变的是每卷项目的**故事素材组织方式**，而非主角命运。

全书采用「现实业务原型 → 修仙化利益冲突 → 可交付软件需求 → 团队协作与验证 → 能力奖励/关系后果」的模式。**不把现实项目完整照搬**，不把非软件行为当成需求完成，也不让单纯写完需求文档获得能力值。

### 六卷与现实业务原型对应
1. **宗门求生**：ERP审批/单据、安防监控、只读设备接入与运营告警；小需求真实交付建立男主职业可信度。
2. **商业扩张**：灵药WMS与仙器制造ERP，重点是批次、复检、冻结与授权例外、BOM/设计版本、采购/生产/工序质检；生产质量问题对人物产生实际代价。
3. **七宗技术大比**：无人系统云平台映射御剑飞行云，云边连接、开放接口、桥接、调度、录像/AI告警分系统；平台成功带来标准权争夺。
4. **天庭甲方**：IP资源运营与灵讯白名单准入，资源共享和独享、合法授权、线路释放、身份控制与申诉；技术和权力边界发生交锋。
5. **天道崩溃**：丹医AI辅助、跨域系统集成及审计事故；揭露系统集中奖励与权责错配。
6. **重构天道**：整合需求治理、权限、质量、追溯、审计、可灰度发布/回滚的经验，以分权规则改革众愿系统。

### 新的长线主题线索
**需求权、验收权、变更权、处置权、收益权**依次升级：从宗门谁签报销，到天下谁有资格提出和修改天道规则。白知微质疑贡献归属，沈听澜维护专业判断权，苏小满维护风险记录，顾不惊最终放弃独断权限，都是同一主题的不同阶段。
