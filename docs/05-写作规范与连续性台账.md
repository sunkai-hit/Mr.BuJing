# 写作规范、连续性与版本台账（V0.1）
> 用途：支持后续「编辑方案→试写→正式稿」协作。当前所有章节均处于策划阶段，未完成正式正文。

## 1. 正文写作原则
1. **故事优先于黑话**：用冲突表现产品方法，不罗列现代产品经理培训材料；术语首次出现须有情境解释。
2. **一章一个主要动作**：每章有明确目标、阻力、行动、后果和尾钩；可以含副线，但不让主线迷失。
3. **笑点要服务角色**：合欢宗女修是独立专业人士，不是男性主角的布景；不靠低俗露骨描写推动剧情。
4. **爽点必须付代价**：项目成功要归因于团队、资源、风险控制和真实验收，系统奖励不免除现实后果。
5. **专业底线**：产品经理不装懂术法；开发决定与测试否决由相关专业角色参与。客户不是一律敌人。
6. **节奏渐进**：前80章高频荒诞喜剧，80—160章展开多宗格局，161章后严肃主线更重但保留诙谐对话。
7. **叙事视角**：第三人称限知，以顾不惊为主要焦点；切换视角须有场景标志，避免随时读心。

## 7. 版本与稿件状态
- V0.1：创作基准和第一卷策划。2026-10-30，已存仓库。
- 正式稿目录建议：novel/volume-01/001-我们只是加一个小功能.md 等；在完成审稿前不得在 README 标注「正式发布」。
- 每章审阅必查：目标与阻力、视角、人物一致性、金额与时间、法阵成本、系统奖励是否真实、伏笔回收、是否有低俗及不尊重角色的描写。
- 修改规则：已确认五项总基准必须征得作者同意；章节细节可以修订，但须同步更新大纲、分镜和台账，防止一处改动引发多份文档不一致。
- 下阶段建议：先审阅前10章节奏与系统数值→试写第1章→审阅确认→正式稿第1章→逐章推进，不提前宣称完成40章正文。
