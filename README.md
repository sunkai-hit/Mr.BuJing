# 我在合欢宗做产品经理

> 仓库代号：**Mr.BuJing**｜主人公：顾不惊（“不惊先生”）
>
> **小说开发状态：策划阶段 · V0.2（2026-10-30）**。尚未进入正式章节连载。

## 一句话梗概

一个在现代软件研发行业被需求变更折磨的产品经理穿越合欢宗，绑定「天道研发修仙系统」：完成真实的软件研发需求增加能力值，与客户有效对线增加生命值。他从宗门数字化建设起步，最终发现天道本身是运行十万年的老旧软件，在改革天道之后回到合欢宗生活。

## 已确认的创作基准（冻结）

1. **基调**：喜剧爽文为主，后期逐渐史诗化。
2. **感情**：一位核心女主（沈听澜），宗门群像与轻度暧昧；不走无边界后宫。
3. **男主能力起点**：技术一般，产品思维、需求分析、沟通谈判、项目与团队管理出色；不能全知全能。
4. **篇幅**：六卷，约 80—100 万字，约 240 章（随正文调节章均字数，目标约 3,300—4,200 字）。
5. **结局**：改革天道、取消唯一管理员的特权后，顾不惊回归合欢宗。

## 核心机制

- 完成并通过真实验收的软件需求：根据价值与难度奖励能力值，基础可 +1；禁止拆单刷分。
- 与客户「对线」成功：不是吵赢，而是澄清诉求、确定边界、双方认可后，生命值上限及当前值获得适度提升（一般 +1；高风险对线可更高）。
- BUG 修复、版本发布、跨团队协作等提供其他有限奖励；质量事故和过度承诺有实际代价。
- 合欢宗的「共鸣之术」是洞察用户愿望的能力，不等于自动理解业务流程；后期关联天道众愿系统。

## V0.2 创作方法：让真实需求长出仙侠故事

小说项目与需求来自作者参与的真实软件研发**通用业务场景**，经合并、匿名化与充分虚构后转化为仙侠世界的项目。写作顺序是「业务痛点 → 人物立场冲突 → 软件方案 → 实现/测试/验收 → 系统奖励与人物代价」，不照搬真实客户和内部资料。

- [现实项目仙侠化改编规则](project-materials/00-现实项目仙侠化改编规则.md)

**改编项目顺序**：第一卷内部审批与护山运营预警；第二卷灵药WMS/仙器ERP；第三卷御剑飞行云平台；第四卷灵讯资源与接入授权；第五卷丹医AI/系统集成风险；第六卷天道共同治理。
**能力点的核心准则**：一个真正独立、可验收的软件研发需求交付成功，能力值基础+1；单凭写方案、开会和签合同不加能力值。客户对线成功需形成有效共识，生命值基础+1。

## 协作与版本原则

此仓库是唯一的创作基准来源。**已确认的五项设定不得在后续写作中擅自改变**；其他细节均为「策划草案」，可通过新版本文档修订。写作遵循「大纲 → 章节方案 → 试写 → 审阅 → 正式稿」，区别策划与实际完成进度，不把草案标为正式章节。
